# 🪱 Tapeworm

Tapeworm is a small Rubika workflow made of three parts:

1. Worm — collects recent messages from Rubika channels.
2. Fly — sends one message to many Rubika accounts in bulk.
3. Inserter — sends extracted text to Ollama, converts it into structured product data, and stores the results in the database.

This project is meant to be used as a full pipeline:

```text
Rubika channels / phone list
        │
        ├───────────────► Worm ──► rubika_messages.json ──► Inserter ──► Database
        │
        └───────────────► Fly ──► bulk_send_results.json
```

---

## Overview of the three projects

### 1) Worm
Worm reads Rubika channel usernames/IDs and fetches the most recent messages from those channels. It saves them as JSON so they can be processed later by the Inserter.

### 2) Fly
Fly is the bulk messaging tool. It reads a list of phone numbers and a message template, then sends the same message to every account in the list using Rubika.

### 3) Inserter
Inserter reads the extracted messages from the JSON file, sends the relevant text to Ollama, and asks the model to return structured product information. The resulting product data is then saved to the database.

---

## Shared Rubika session

Both Worm and Fly use the same Rubika session name:

```python
SESSION_NAME = "my_session"
```

This means they are designed to reuse the same authenticated Rubika session file, which is typically:

```text
my_session.session
```

Important: for the shared session to actually be reused, run Worm and Fly from the same working directory, or keep the same session file available in the directory where the scripts are executed. If the session file is in a different directory, Rubpy may treat it as a different session and ask you to log in again.

## Project requirements

### Python requirements
From the project root, install the Python dependencies:

```bash
pip install -r requirements.txt
```

The required package list is:

```text
requests
rubpy
```

### Ollama requirement
The Inserter needs Ollama running locally with a model available, for example:

```bash
ollama pull qwen3:4b
```

Then your app should point to the local Ollama base address, usually:

```text
http://localhost:11434
```

### .NET requirement
The Inserter is a .NET application and requires:

- .NET 10 SDK
- SQL Server connection string configured in the app
- `rubika_messages.json` generated by Worm

## 1. 🪱 Worm

### What Worm does
For each configured channel, Worm fetches the last 50 messages and saves:

- message text
- captions for media messages
- timestamps in UTC
- channel metadata
- shareable URLs when available

### Files used by Worm
Inside the `worm/` folder:

```text
worm/
├── rubikaworm.py
├── rubika_channels.txt
├── rubika_messages.json
├── my_session.session   # created after login
└── my_session.rp       # session sidecar if Rubpy creates it
```

### How to configure Worm
Create or edit `worm/rubika_channels.txt` and add one channel per line.

Examples:

```text
my_channel
@my_channel
c0xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

You may use either:
- public channel usernames
- channel usernames prefixed with `@`
- channel GUIDs

### First login
The first time you run Worm, Rubpy will ask for:

1. your phone number
2. the login code sent to the Rubika app

After successful authentication, `my_session.session` is created and reused.

### Run Worm
From the project root:

```bash
python worm/rubikaworm.py
```

Or from inside the `worm/` folder:

```bash
cd worm
python rubikaworm.py
```

### Output
Worm writes the resulting message archive to:

```text
worm/rubika_messages.json
```

This file is the input used by the Inserter.

## 2. 🪰 Fly

Fly is the bulk sender. It reads a list of Rubika account phone numbers and a message file, then sends the same text message to each target.

### What Fly does
For each phone number, Fly:

1. adds the number to the Rubika address book
2. waits a moment for the contact to register
3. sends the message
4. writes the success or failure result to JSON

### Files used by Fly
Inside the `fly/` folder:

```text
fly/
├── rubikafly.py
├── phonenumbers.txt
├── message.txt
├── bulk_send_results.json
├── my_session.session   # shared Rubika session file
└── my_session.rp
```

### How to configure Fly
Create or edit:

- `fly/phonenumbers.txt` — one phone number per line
- `fly/message.txt` — the message text to send

Example `phonenumbers.txt`:

```text
+989123456789
+989987654321
```

Example `message.txt`:

```text
Hello! This is a bulk Rubika message.
```

### Shared session behavior
Fly intentionally uses the same session name as Worm:

```python
SESSION_NAME = "my_session"
```

This keeps the same authenticated Rubika session for both scripts. If you want both tools to share the same session, keep the session file in the same working directory when they are run.

### Run Fly
From the project root:

```bash
python fly/rubikafly.py
```

Or from inside the `fly/` folder:

```bash
cd fly
python rubikafly.py
```

### Output
Fly writes a summary and per-phone results to:

```text
fly/bulk_send_results.json
```

## 3. 📦 Inserter

Inserter is the database insertion and AI extraction part of the system. It takes the JSON generated by Worm, sends relevant messages to Ollama, extracts structured product data, and saves the result to the database.

### Requirements
Make sure you have:

- .NET 10 SDK installed
- Ollama running locally
- a valid model available, such as `qwen3:4b`
- a SQL Server database and connection string
- the output file from Worm: `worm/rubika_messages.json`

### Configuration
The app reads configuration from `Inserter/Inserter/appsettings.json` and optionally from user secrets in development.

Example configuration:

```json
{
  "ConnectionStrings": {
    "AppDbContext": "Server=localhost;Database=Tapeworm;Trusted_Connection=True;TrustServerCertificate=True;"
  },
  "Ollama": {
    "BaseAddress": "http://localhost:11434",
    "Model": "qwen3:4b"
  },
  "MessagesFilePath": "../worm/rubika_messages.json"
}
```

The code in `Program.cs` expects:

- `ConnectionStrings:AppDbContext`
- `Ollama:BaseAddress`
- `MessagesFilePath`

### Run Inserter
From the `Inserter` folder:

```bash
cd Inserter
dotnet restore
dotnet run
```

Or from the project root if the solution is already built:

```bash
dotnet run --project Inserter/Inserter/Inserter.csproj
```

### API endpoint
Once the app is running, call:

```http
GET /Products/Insert
```

For example:

```text
http://localhost:5010/Products/Insert
```

This endpoint will:

1. read the extracted Rubika messages
2. send the relevant text to Ollama
3. parse the model response into structured product data
4. save the records to the database

## Recommended full workflow

1. Install Python requirements:

```bash
pip install -r requirements.txt
```

2. Configure `worm/rubika_channels.txt`.

3. Run Worm:

```bash
python worm/rubikaworm.py
```

4. Ensure Ollama is running and the model is available.

5. Configure the Inserter connection string and messages path.

6. Run the Inserter:

```bash
cd Inserter
dotnet run
```

7. Call the Insert endpoint:

```text
http://localhost:5010/Products/Insert
```

8. If needed for bulk outreach, run Fly:

```bash
python fly/rubikafly.py
```

## Notes

- The session file is the key to staying logged in to Rubika.
- The shared session name is intentionally `my_session` for both Worm and Fly.
- If you change login sessions or use a different directory for each script, Rubpy may create a different session and force a fresh login.
- Always keep `rubika_messages.json` up to date before running the Inserter.
